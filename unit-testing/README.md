# unit-testing

单元测试生成与执行。

## 触发词

- "单元测试" / "写单测" / "生成测试"
- "跑测试" / "单测"

## 功能

1. 独立生成：指定代码文件或模块，AI 读取代码后自动生成单元测试、运行、修复失败用例
2. 被 daily-workflow 第六步自动引用

## 执行流程

1. 确认测试范围（独立模式手动指定 / daily-workflow 模式从设计文档取）
2. 生成单元测试文件（正常路径 → 边界条件 → 错误处理 → 状态流转 → 用户交互）
3. 运行测试，全部通过则输出报告
4. 有失败则分析原因并修复（最多 3 次），超限标记为需人工处理
5. 输出测试报告

## 个性化配置

`references/` 目录存放用户可编辑的参考配置，换团队/换技术栈时替换即可：

- `frontend-testing.md` — 前端测试框架配置（Jest/Vitest、Mock 策略、覆盖率阈值、编写规范）

## 首次运行

如果项目中不存在 `jest.config.js` 或 `vitest.config.ts`，AI 会按 `references/testing-framework.md` 中的指引自动安装依赖并创建配置文件。

## 自我学习

本 skill 具备独立的学习和反馈机制，详见 `LEARNING.md`。

- 每次用户对 AI 输出做修改/驳回/补充时自动记录反馈
- 同类修改 ≥2 次建议更新规范，驳回 ≥1 次下次规避，确认 ≥3 次固化最佳实践
- 所有学习记录和沉淀的规范更新都在 `LEARNING.md` 中可追溯

## 飞书集成（可选）

本 skill 支持三种输出方式：
1. **对话输出**（默认）：直接在对话中展示
2. **飞书文档**：需安装 `feishu-doc` skill 并配置凭证
3. **本地 MD 文件**：自动保存到 `{SKILLS_DIR}/unit-testing/output/{项目名}/`
