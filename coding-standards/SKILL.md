# Skill: 编码规范

## 触发词
- 编码规范 / coding standards / 代码规范
- 这个怎么写 / 写法 / 规范写法
- 检查规范 / 规范检查

## 用途

1. **规范查询**：用户问"xxx 怎么写"、"xxx 的规范是什么"时，直接给出符合项目规范的写法
2. **代码风格检查**：用户提供代码片段，检查是否符合项目编码规范，给出修正建议
3. **新代码生成**：在 daily-workflow 或其他场景生成代码时，作为编码规范基线被引用

## 规范内容

以下为通用编码规范分类，各分类的具体规则、配置值和代码示例详见 `references/tech-stack.md`。

### 命名规范

统一文件和代码的命名规则，包括文件命名约定（组件、页面、工具函数等）和代码标识符命名约定（变量、函数、常量、类型等），详见 `references/tech-stack.md`。

### 格式化配置

代码格式化工具的配置项和对应风格，包括缩进、引号、分号、尾逗号等，详见 `references/tech-stack.md`。

### Lint 规则

静态检查工具的核心规则，包括变量声明、函数风格、对象与数组、复杂度控制、项目特有规则等，详见 `references/tech-stack.md`。

### 类型规范

类型系统的使用规则，包括类型定义方式（interface vs type）、类型使用要求、严格模式建议等，详见 `references/tech-stack.md`。

### 组件/模块规范

组件或模块的定义方式、生命周期管理、属性传递、条件渲染等，详见 `references/tech-stack.md`。

### 状态管理规范

全局状态管理的模型定义、组件中的使用方式等，详见 `references/tech-stack.md`。

### UI 组件库规范

UI 组件库的引入方式、常用组件使用规范、反馈组件规范等，详见 `references/tech-stack.md`。

### 接口请求规范

接口定义方式、错误处理策略、请求与响应类型定义等，详见 `references/tech-stack.md`。

### 样式规范

样式方案的选择与使用规则，包括样式文件组织、命名约定、全局样式与组件样式的区分等，详见 `references/tech-stack.md`。

### Git 规范

Commit Message 格式、分支命名与管理约定，详见 `references/tech-stack.md`。

### 代码质量

文件与函数的行数限制、嵌套深度控制、注释规范、代码整洁原则等，详见 `references/tech-stack.md`。

## 执行模式

### 模式一：规范查询

用户问"xxx 怎么写"时，结合本文件的通用分类和 `references/tech-stack.md` 的具体规则，直接给出符合规范的代码示例，并标注对应的规范条目。

### 模式二：代码风格检查

用户提供代码片段或指定文件，按以上规范逐项检查，输出：
- 不符合项列表（规范条目 + 问题描述 + 修正建议）
- 修正后的代码

结果可保存到本地 `{SKILLS_DIR}/coding-standards/output/{项目名}/[检查报告名].md`

### 模式三：被 daily-workflow 引用

在 daily-workflow 的第三步（代码开发）中，本 skill 的规范内容作为编码基线被自动加载，生成的代码必须符合以上所有规范。

## References（参考配置）

`references/` 目录存放用户可编辑的参考配置，每次执行前自动读取该目录下所有文件。换团队/换技术栈时替换文件内容即可，无需修改 SKILL.md。

## 自我学习

学习规则与反馈日志详见 `LEARNING.md`。

核心机制：
- **触发时机**：用户对 AI 输出做了修改/驳回/补充时自动记录
- **策略优化**：同类修改 ≥2 次建议更新规范，驳回 ≥1 次下次规避，确认 ≥3 次固化最佳实践
- **执行流程**：识别 → 提出 → 用户确认 → 执行 → 记录到 LEARNING.md
- **变更同步**：规范更新后同步更新 SKILL.md 对应章节

每次执行前读取 LEARNING.md 中的"用户偏好"和"已沉淀的规范更新"，将学到的知识应用到当前输出中。
