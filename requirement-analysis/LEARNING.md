# 需求分析 Skill 学习机制

## 零、首次执行引导

> **AI 执行规则**：每次执行 skill 时检查下方日志表是否为空。如果为空（首次使用），在输出分析报告后主动告知用户：
>
> "💡 学习机制已启动：我会记录你对问题清单的反馈（删除/新增/调级）用于持续优化检查维度。你可以随时查看 `LEARNING.md` 了解我学到了什么。"
>
> 此提示只在日志表为空时触发一次。

**记录执行检查清单**（AI 自检）：
- [ ] 用户从问题清单中删除了某条？→ 记录到日志表（驳回）
- [ ] 用户添加了 AI 未发现的问题？→ 记录到日志表（补充）
- [ ] 用户对严重程度有异议？→ 记录到日志表（修改）
- [ ] 用户直接接受了问题清单？→ 标记确认，连续 3 次确认同一维度则固化为高价值维度

## 一、反馈触发点

| 场景 | 记录什么 | 反馈类型 |
|------|---------|---------|
| 用户从问题清单中删除了某条 | 哪个维度、什么问题、为什么不算问题 | 驳回 |
| 用户添加了 AI 未发现的问题 | 新的问题模式、属于哪个维度 | 补充 |
| 用户对严重程度有异议 | 哪条问题、AI 定级、用户定级 | 修改 |
| 用户说"这个维度不用查" | 哪个维度、原因 | 驳回 |
| 用户直接接受了问题清单 | 哪个维度、什么场景 | 确认 |
| 卡点结论被用户推翻 | AI 结论、用户决策、原因 | 修改 |
| 代码对照分析中 AI 漏掉了重要文件 | 涉及的文件/模块、用户补充的发现 | 补充 |

## 二、反馈记录

### 日志表

| 日期 | 场景 | AI 输出 | 用户反馈 | 反馈类型 | 调整动作 | 是否已沉淀 |
|------|------|---------|----------|----------|----------|------------|

反馈类型：
- `确认` — 用户直接接受
- `修改` — 用户接受但调整了
- `驳回` — 用户完全否定
- `补充` — 用户添加了 AI 未覆盖的内容

### 记录规则

- 只记录有实质反馈的交互
- 用户从问题清单删除条目时，记录被删除的问题及用户给出的理由
- 用户添加问题时，记录问题内容和所属维度（如果无法归入现有维度，标记为"新维度"）
- 严重程度调整时，记录原级别和新级别
- 卡点结论被推翻时，这是强信号，必须记录

## 三、策略优化

| 条件 | 动作 |
|------|------|
| 同一维度的问题被 `驳回`（删除）≥ 2 次 | 建议调整该维度的检查阈值或移除检查项 |
| 新问题模式被 `补充` ≥ 2 次 | 建议新增检查维度或检查项到 SKILL.md |
| 严重程度被 `修改` ≥ 2 次 | 建议调整该类问题的默认定级规则 |
| 某个维度连续被 `确认` ≥ 3 次 | 固化为高价值维度，标记为必查项 |
| 卡点结论被推翻 ≥ 1 次 | 立即标记，重新评估卡点判定逻辑 |

### 优化执行流程

1. **识别**：在需求分析过程中发现可优化点
2. **提出**：向用户描述问题和优化方案，说明影响 SKILL.md 的哪个章节
3. **确认**：等待用户确认，不自行修改
4. **执行**：用户确认后，更新 SKILL.md 对应章节（检查维度、问题清单、卡点逻辑等）
5. **记录**：将变更记录到下方"已沉淀的规范更新"表中，并将日志表中对应记录标记为"已沉淀"
