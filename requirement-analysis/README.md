# requirement-analysis

需求分析与 PRD 质量评审。

## 触发词

- "需求分析" / "分析PRD" / "审PRD"
- "看看这个需求" / "评审需求"

## 功能

1. 独立评审 PRD：给 PRD 链接，输出质量评估结论（通过/有疑问/严重问题）
2. 被 daily-workflow 第一步自动引用

## 分析维度

两层分析：

**PRD 文本层**：交互与视觉、边界条件、状态流转、数据与接口、逻辑一致性、异常与降级

**代码对照层**：组件结构兼容性、数据结构兼容性、技术债与隐患、影响范围评估

## 卡点机制

分析结果给出三级结论：
- ✅ 通过：可进入设计阶段
- ⚠️ 有疑问：建议澄清，但用户说"继续"也可以放行
- ❌ 严重问题：建议打回，用户坚持也可继续（记录风险）

用户拥有最终决策权，AI 只提供建议。

## 个性化配置

`references/` 目录存放用户可编辑的引导配置，换团队/换技术栈时替换即可：

- `frontend-concerns.md` — 需求关注点（用户交互、刷新缓存、多标签页、加载异常、路由导航等）

## 飞书集成（可选）

本 skill 支持三种输出方式：
1. **对话输出**（默认）：直接在对话中展示
2. **飞书文档**：需安装 `feishu-doc` skill 并配置凭证
3. **本地 MD 文件**：自动保存到 `{SKILLS_DIR}/requirement-analysis/output/{项目名}/`

## 自我学习

本 skill 具备独立的学习和反馈机制，详见 `LEARNING.md`。

- 每次用户对 AI 输出做修改/驳回/补充时自动记录反馈
- 同类修改 ≥2 次建议更新规范，驳回 ≥1 次下次规避，确认 ≥3 次固化最佳实践
- 所有学习记录和沉淀的规范更新都在 `LEARNING.md` 中可追溯
