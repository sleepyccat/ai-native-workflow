# 🚀 开发工作流 — 使用说明

> 一个开发自动化 Skill，用 AI 自动化开发全流程：需求分析 → 设计文档 → 代码开发 → 接口联调 → AI CR → 单元测试 → 提测。同时支持日报、周报、季度/年度总结的自动生成。

所有产出文档统一输出到项目根目录 `dw-docs/`，每个需求一个文件夹，方便管理和移交。飞书文档为可选同步渠道（仅开发设计和提测阶段询问）。

---

## 🚀 使用方式

### 开始新需求

```
开启 dw https://xxx.feishu.cn/wiki/xxx（飞书 PRD 链接）
开启 dw ./docs/PRD.md（本地 PRD 文件）
开启 dw（交互式输入需求信息）
```

AI 会自动按七步流程推进，每步完成后等你确认再继续。

> 第一步会自动生成 Git 分支名并创建分支，后续通过分支名自动关联需求上下文。

### 跟进需求（只做需求分析）

```
跟进 xxx https://xxx.feishu.cn/wiki/xxx（飞书 PRD 链接）
跟进 xxx ./docs/PRD.md（本地 PRD 文件）
```

不创建 Git 分支，只做需求分析。AI 会询问飞书项目链接并写入需求分析文档，方便后续跟进。状态只有"跟进中"和"已上线"两种。

## 📢 常用命令

| 说什么 | 做什么 |
|--------|--------|
| `开启 dw` + PRD链接 | 🚀 启动七步流程 |
| `开启 dw` + PRD链接 + `模块：xxx` | 🚀 启动流程并指定模块专项规范 |
| `跟进 xxx` + PRD链接 | 📋 跟进模式，只做需求分析（不建分支，记录飞书项目链接） |
| `继续 dw` | 🔗 自动通过 Git 分支名匹配需求，从断点继续（也支持接手移交的需求） |
| `更新 dw` + 状态 | 📝 手动更新需求状态（如"已上线"） |
| `记录` / `记一下` / `log` + 工作内容 | 📌 快速记录零散工作（bug fix、会议、调研等） |
| `移交 [需求名] 给 [人名]` | 🤝 生成移交文档（直接把文件夹交给接手人即可） |
| `导出 skill 到 [平台]` | 📦 将 skill 导出为 Cursor/Kiro/Windsurf/Trae 格式 |
| `新增模块规范：xxx` | 📦 创建新的模块专项规范文件 |
| `写周报` | 📊 自动汇总本周工作生成周报（含效率度量数据） |
| `写季度总结` / `Q1总结` | 📋 生成季度总结 |
| `年度总结` | 📋 生成年度总结 |

## 📋 流程概览

```
PRD链接 → ① 需求分析 → ② 设计文档 → ③ 代码开发 → ④ 接口联调(可跳过) → ⑤ AI CR → ⑥ 单元测试 → ⑦ 提测
                                                          ↑
                                                   无接口文档时先 Mock
                                                   有接口文档后联调替换
```

每步都有确认点，你说"确认"才会进入下一步。

### 待确认项交互

在需求分析和设计文档阶段，如果发现矛盾点或需要你决策的地方，AI 会直接在文档末尾写出选择题。你在文件中勾选/填写答案后保存，告诉 AI "继续"即可。

## 🤝 需求移交

移交变得非常简单：

1. 告诉 AI "移交 [需求名] 给 xxx"
2. AI 在需求文件夹中生成 `handover.md`
3. **把整个需求文件夹交给接手人**（复制/Git/IM 均可）
4. 接手人放入自己的 `dw-docs/` → 切分支 → "继续 dw"

所有上下文都在文件夹里，不依赖飞书权限、不怕文档被覆盖。

## ❓ 常见问题

**Q: 飞书文档怎么用？**
> 飞书是可选的。只在设计文档和提测文档完成后，AI 会问你"要不要同步一份飞书文档"。说不需要就不会创建。

**Q: 流程中断了怎么恢复？**
> 只要你在对应的 Git 分支上，直接说 `继续 dw` 即可。AI 会通过当前分支名自动匹配需求，从断点继续。

**Q: 可以同时推进多个需求吗？**
> 可以。每个需求在 `dw-state.json` 的 `requirements` 数组中独立一个条目，`dw-daily.md` 中同一天可以有多个需求的记录，通过需求名区分。

**Q: 一个需求要在同一个对话里跑完七步吗？**
> 不建议。每步完成后开新对话，下次说"继续 dw"即可从断点恢复。这样做有三个好处：① 节省 token 消耗；② 避免长上下文导致 AI 注意力分散；③ 每步的 references 文件不同，新对话加载更精准。

**Q: 文档中的"待确认项"是什么？**
> 当 AI 在分析需求或做设计时发现矛盾点/需要你决策的地方，会直接在文档末尾写出选择题。你在文件中勾选答案后保存，告诉 AI "继续"，它会读取你的选择并继续完善文档。

**Q: 流程规范不合理怎么办？**
> AI 会主动识别可优化的点。确认后 AI 会自动更新规范及所有关联文件，即刻生效。
