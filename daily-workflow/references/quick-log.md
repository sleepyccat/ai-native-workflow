# 快速记录规范

## 触发

用户说"记录"、"记一下"、"log" 等关键词 + 工作内容描述

## 用途

记录不走七步流程的工作，包括两类：

1. **零散工作**：一次性事件（临时 bug fix、技术调研、开会、协助排查问题等）
2. **跟进需求**：需要持续跟进但不亲自开发的需求（评审分配、推动进度、确认上线等）

两类都确保周报和总结时数据完整。区别在于：零散工作记一次就完事，跟进需求可以多次追加进度。

## 执行流程

1. 读取 `dw-state.json`，在 `requirements` 数组中新增一个条目：
   - `name`：用户描述的工作内容摘要
   - `branch`：留空（如用户提到了分支则填入）
   - `status`：`已完成`（默认）或用户指定的状态
   - `pm_url`：null
   - `daily_log`：当天日期 → [工作内容]
2. 在 `daily-log.md` 当天日期区域追加记录（格式见 `general-rules.md` 日报更新章节）
3. 在索引（飞书 `AI-docs/index` 或本地 `dw-index.md`）零散工作索引中追加条目，并根据内容更新技术标签索引
4. 完成后简短确认："已记录 ✓"

## 示例

### 零散工作（一次性）

- "记录：修了个线上列表展示 bug" → 新增一行，需求名"修复列表展示bug"，状态"已完成"
- "记一下：今天参加了技术方案评审会" → 新增一行，需求名"技术方案评审会"，状态"已完成"
- "log：协助后端排查订单接口超时问题，进行中" → 新增一行，需求名"协助排查订单接口超时"，状态"进行中"

### 跟进需求（持续追加）

- "记录：评审了「商品分时段售卖」需求，分配给张三开发" → 新增一行，需求名"商品分时段售卖"，状态"跟进中"，分支留空
- "记录：「商品分时段售卖」联调评审通过" → 匹配到已有行，追加到当天日期列
- "记录：「商品分时段售卖」已上线" → 匹配到已有行，追加到当天日期列，状态更新为"已上线"

**识别规则**：用户描述中包含需求名（用「」包裹）+ 评审/分配/跟进/推动等关键词 → 判定为跟进需求，状态设为"跟进中"而非"已完成"。

## 规则

- 快速记录不创建飞书管理文件，不创建 Git 分支，不走七步流程
- **跟进需求的 branch 字段始终为空**——这是汇报时区分"开发需求"和"跟进需求"的依据（有 branch = 开发，无 branch = 跟进/零散）
- 如果用户描述的内容看起来是一个需要亲自开发的完整需求（而非跟进或零散工作），提醒用户是否要走"开启 dw"流程
- 同一天对同一工作项的多次记录，追加到 `daily-log.md` 同一需求下和 `dw-state.json` 同一条目的 `daily_log` 中，不重复新增
- 跟进需求后续追加时，通过需求名匹配已有条目（支持模糊匹配），追加日报并按需更新状态
