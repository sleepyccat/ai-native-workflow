# 快速记录规范

## 触发

用户说"记录"、"记一下"、"log" 等关键词 + 工作内容描述

## 用途

记录不走七步流程的工作，包括三类：

1. **零散需求**：有明确功能名但不走完整流程的小事（临时 bug fix、小优化等）
2. **跟进需求**：需要持续跟进但不亲自开发的需求（评审分配、推动进度、确认上线等）
3. **杂项事务**：与业务需求无关的纯事务性工作（开会、调研、协助、学习、搭环境等）

三类都确保周报和总结时数据完整。

## 分类识别规则

AI 根据以下信号自动判断归类：

| 信号 | 归类 | 存储位置 |
|------|------|----------|
| 有明确需求/功能名（用「」包裹或能提炼出功能名） | 跟进需求 → `requirements` | Doing/Done 区 |
| 用户提到了 Git 分支 | 零散需求 → `requirements` | Doing/Done 区 |
| 修了个 bug / 做了个小优化（有具体功能点） | 零散需求 → `requirements` | Doing/Done 区 |
| 纯事务性（开会、调研、协助、学习、分享、搭环境） | 杂项事务 → `misc_log` | 仅日报表格 |
| 无法判断时 | 问用户"这个要作为需求跟踪吗？" | — |

**核心区分**：有后续状态流转需要的进 requirements，纯"做了就完事"的杂事进 misc_log。

## 执行流程

### 零散需求 / 跟进需求 → requirements

1. 读取 `dw-state.json`，在 `requirements` 数组中新增条目：
   - `name`：工作内容摘要
   - `branch`：留空（跟进需求始终为空，零散需求如用户提到分支则填入）
   - `status`：`已完成`（零散默认）/ `跟进中`（跟进需求）/ 用户指定
   - `pm_url`：null
   - `daily_log`：当天日期 → [工作内容]
2. 在 `dw-daily.md` Doing/Done 区创建或追加需求条目
3. 在 `dw-index.md` 零散工作索引中追加条目
4. 确认："已记录 ✓"

### 杂项事务 → misc_log

1. 读取 `dw-state.json`，在 `misc_log` 数组中追加：
   ```json
   {
     "date": "2026-06-10",
     "content": "参加技术方案评审会",
     "tags": ["会议"]
   }
   ```
2. 在 `dw-daily.md` **顶部日报区**的表格中追加一行（需求列填 `—`，状态列填 `—`）
3. **不在 Doing/Done 区创建条目**（杂事不需要状态跟踪）
4. 确认："已记录 ✓"

### tags 参考值

| 标签 | 适用场景 |
|------|----------|
| 会议 | 评审会、周会、技术分享、1v1 |
| 协助 | 帮别人排查问题、搭环境、答疑 |
| 调研 | 技术调研、方案对比、学习新技术 |
| 运维 | 发版、配置变更、监控处理 |
| 团队 | 带新人、写文档、流程优化 |

AI 根据内容自动打标签，用户也可自定义。

## 示例

### 零散需求

- "记录：修了个线上优惠券展示 bug" → requirements，需求名"修复优惠券展示bug"，状态"已完成"
- "log：协助后端排查订单接口超时问题，进行中" → requirements，需求名"协助排查订单接口超时"，状态"进行中"

### 跟进需求

- "记录：评审了「咖啡时段售卖」需求，分配给张三开发" → requirements，需求名"咖啡时段售卖"，状态"跟进中"
- "记录：「咖啡时段售卖」已上线" → 匹配已有条目，追加日志，状态更新为"已上线"

### 杂项事务

- "记一下：今天参加了技术方案评审会" → misc_log，tags: ["会议"]
- "记录：帮新同事搭了开发环境" → misc_log，tags: ["协助", "团队"]
- "log：研究了下 Vite 5 的新特性" → misc_log，tags: ["调研"]

## 规则

- 快速记录不创建 Git 分支，不走七步流程
- **跟进需求的 branch 字段始终为空**——这是汇报时区分"开发需求"和"跟进需求"的依据（有 branch = 开发，无 branch = 跟进/零散）
- 如果用户描述的内容看起来是一个需要亲自开发的完整需求（而非跟进或零散工作），提醒用户是否要走"开启 dw"流程
- 同一天对同一工作项的多次记录，追加到已有条目中，不重复新增
- 跟进需求后续追加时，通过需求名匹配已有条目（支持模糊匹配），追加日报并按需更新状态
- 杂项事务不参与度量统计（不影响需求完成数、平均耗时等指标）
- 周报汇总时从 `requirements` + `misc_log` 两个来源合并，杂项事务归入"其他工作"章节
