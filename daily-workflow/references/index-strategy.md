# 结构化索引（长期记忆层）

为解决跨会话记忆丢失和文档积累后检索效率低的问题，维护一个全局索引文档作为结构化记忆入口。

- **位置**：`{PROJECT_ROOT}/dw-docs/dw-index.md`

## 索引文档格式

### 需求索引（按季度分组，组内按时间倒序）

```
## 2026 Q2
| 日期 | 需求名 | 状态 | 分支名 | 关键技术点 | 文档路径 |
|------|--------|------|--------|------------|----------|
| 04/28 | 优惠券列表重构 | 已上线 | feature/coupon-list | Antd Table 虚拟滚动 + 接口分页 | [需求分析](./优惠券列表重构/requirements.md) |
| 04/15 | 资源位管理 | 开发中 | feature/resource-mgr | 动态表单 + 拖拽排序 | [需求分析](./资源位管理/requirements.md) |

## 2026 Q1
| 日期 | 需求名 | 状态 | 分支名 | 关键技术点 | 文档路径 |
...
```

### 零散工作索引（按月分组）

```
## 零散工作 - 2026/04
| 日期 | 工作内容 | 状态 |
|------|----------|------|
| 04/30 | 修复优惠券展示bug | 已完成 |
| 04/25 | 技术方案评审会 | 已完成 |
```

### 技术标签索引（底部维护）

```
## 技术标签索引
- 优惠券：优惠券列表重构(04/28)、优惠券展示bug(04/30)
- 性能优化：优惠券列表重构(04/28)
- 资源位：资源位管理(04/15)
```

## 需求摘要区

每个需求的 `requirements.md` 头部维护结构化摘要：

```
> **摘要**
> - 一句话描述：xxx
> - 核心技术方案：xxx
> - 涉及模块/页面：xxx
> - 最终状态：xxx
> - 完成日期：xxx
```

## 索引维护时机

| 时机 | 操作 |
|------|------|
| 第一步需求分析完成 | 在 `dw-index.md` 需求索引中插入新条目；在 requirements.md 头部创建摘要区 |
| 第二步设计文档完成 | 更新摘要区"核心技术方案"；更新 `dw-index.md` 条目"关键技术点" |
| 第七步提测完成 | 更新 `dw-index.md` 条目状态；更新摘要区最终状态 |
| 状态变更（已上线等） | 更新 `dw-index.md` 条目状态；更新摘要区最终状态和完成日期 |
| 快速记录 | 在 `dw-index.md` 零散工作索引追加条目 |
| 技术标签变化 | 更新 `dw-index.md` 技术标签索引 |

## 检索路径

| 场景 | 检索路径 |
|------|----------|
| 写周报 | 读 `dw-state.json` 各需求的 `daily_log` + `dw-daily.md` 本周记录 |
| 写季度总结 | 读 `dw-index.md` 对应季度 → 按需读摘要区 → 极少数读完整文档 |
| 写年度总结 | 读 `dw-index.md` 全部季度 + 技术标签 → 按需读摘要区 |
| 继续 dw | 读 `dw-state.json` 找到条目 → 读取 context |
| 了解某个需求 | 读 `dw-index.md` → 进入对应文件夹 → 读 requirements.md 摘要区 |
