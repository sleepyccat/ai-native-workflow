# 度量报告输出规范

## 触发方式

| 用户说 | 输出内容 | 输出位置 |
|--------|----------|----------|
| "看看效率数据" / "度量报告" / "效率分析" | 完整度量汇总报告 | 对话中展示 |
| "写周报" | 周报中自动包含效率数据章节 | 飞书/本地文档 |
| "写季度总结" / "年度总结" | 总结中包含趋势分析 | 飞书/本地文档 |
| "重新计算 baseline" | 重新计算并更新 baseline | dw-state.json |

## 计算规则

### 平均值计算

- 只统计有完整度量数据（`total_duration_minutes` 不为 null）的需求
- 跟进型需求（无 metrics 或 metrics 为 null）不纳入统计
- 进行中的需求单独列出，标注"进行中"

### 占比计算

- 各阶段耗时占比 = 该阶段平均耗时 / 所有阶段平均耗时之和 × 100%
- 跳过的阶段（null）不参与计算

### 修改率

- 修改率 = (revisions + rejections) / turns × 100%
- 反映 AI 输出的一次通过率

### CR 精准率

- CR 精准率 = (cr_issues_total - cr_false_positives) / cr_issues_total × 100%
- 无 CR 数据时显示 "-"

### 与基线对比

- 有 baseline 时自动计算变化百分比
- 正向变化（耗时减少、精准率提升）用 ↓/↑ + 绿色标注
- 负向变化用 ↑/↓ + 红色标注
- 无 baseline 时该章节不展示，改为提示"需完成 5 个需求后建立基线"

## 周报中的效率数据章节

当用户说"写周报"时，在周报文档中自动包含以下章节：

```markdown
## 本周效率数据

- 本周完成需求：X 个（S:X, M:X, L:X）
- 平均需求耗时：X 小时
- 平均交互轮次：X 轮/需求
- 修改率：X%（vs 基线 X%）
- CR 精准率：X%
- 测试覆盖率均值：X%
- 本周 Bug 发现数：X 个

**效率趋势**：[与上周/基线对比的一句话总结]
```

```markdown
### 关键洞察

1. [趋势观察]

3. [最佳实践沉淀]
```

## 注意事项

- 度量报告是只读输出，不修改 dw-state.json
- 数据不足时（<3 个有完整度量的需求），提示用户"数据样本不足，建议完成更多需求后再查看趋势"
- 对外分享时可脱敏（隐藏需求名、分支名），用户说"脱敏输出"时启用
