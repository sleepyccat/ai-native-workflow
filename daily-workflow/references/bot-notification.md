# 飞书机器人通知规范

## 配置

Webhook URL 从 `{SKILLS_DIR}/config.json` 的 `feishu.bot_webhook_url` 字段读取。

首次使用需复制模板并填写：
```bash
cp {SKILLS_DIR}/config.example.json {SKILLS_DIR}/config.json
# 编辑 config.json，填写你的 bot_webhook_url
```

## 发送方式

通过 PowerShell `Invoke-RestMethod` 发送（URL 从 config.json 读取）：

```powershell
$webhookUrl = (Get-Content {SKILLS_DIR}/config.json | ConvertFrom-Json).feishu.bot_webhook_url
Invoke-RestMethod -Uri $webhookUrl -Method Post -ContentType "application/json" -Body '{"msg_type":"text","content":{"text":"<消息内容>"}}'
```

## 通知规则

每个步骤完成（用户确认后）立即发送通知。消息内容包含：**项目名** + 需求名 + 完成了什么 + 文档链接（如有产出）。

项目名取当前工作目录的 basename（与 dw-state.json 中的 `project` 字段一致）。

## 七步流程通知

### 第一步：需求分析完成

```
[{项目名}] 「{需求名}」需求分析已完成 ✅
分支：{分支名}
需求分析文档：{文档链接}
```

### 第二步：设计文档完成

```
[{项目名}] 「{需求名}」设计文档已完成 ✅
设计文档：{文档链接}
```

### 第三步：代码开发完成

```
[{项目名}] 「{需求名}」代码开发已完成 ✅
改动文件：{文件数}个
下一步：{待联调/AI CR}
```

### 第四步：接口联调完成

```
[{项目名}] 「{需求名}」接口联调已完成 ✅
替换接口：{接口数}个
```

### 第五步：AI CR 完成

```
[{项目名}] 「{需求名}」AI Code Review 已完成 ✅
问题统计：P1({n})  P2({n})  P3({n})
走查报告：{文档链接}
```

### 第六步：单元测试完成

```
[{项目名}] 「{需求名}」单元测试已完成 ✅
测试用例：{总数}个，通过{通过数}个
单元测试报告：{文档链接}
```

### 第七步：提测完成

```
[{项目名}] 「{需求名}」已提测 🚀
分支：{分支名}
提测文档：{文档链接}
```


## 规则

- 所有通知以 `[{项目名}]` 前缀开头（项目名 = 工作目录 basename）
- 发送失败不阻塞流程，只在对话中提示"通知发送失败"
- 用户说"关闭通知"→ 临时禁用，说"开启通知"→ 恢复
- 用户可自定义通知范围（如"只通知提测和上线"）
- 消息中的文档链接：飞书后端使用飞书文档完整 URL，本地后端使用本地文件路径

## 本地模式（storage_backend = local）

当未配置飞书 MCP 或飞书 Webhook 时：

### 行为

- **不发送任何通知**，无 Webhook 可用
- 每个步骤完成后，在对话中输出简短确认信息（替代机器人通知）：

```
[{项目名}] 「{需求名}」{步骤}已完成 ✓
```

- 文档链接替换为本地文件路径

### 通知范围

- 本地模式下不支持自定义通知范围，所有确认信息直接在对话中输出
- 用户说"关闭通知"→ 本地模式下停止输出对话确认信息
- 用户说"开启通知"→ 恢复对话确认信息输出
