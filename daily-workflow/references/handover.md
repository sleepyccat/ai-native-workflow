# 需求移交规范

## 触发

用户说"移交 [需求名/分支名] 给 [人名]"

## 用途

将某个进行中的需求移交给其他同事，生成完整的移交文档并通知对方。无论对方是否使用本 skill，都能通过移交文档了解进度和上下文。

## 执行流程

### 1. 定位需求

- 用户提供需求名（支持模糊匹配）或分支名
- 从 `dw-state.json` 中匹配（飞书配置时也可从 `AI-docs/index` 匹配）
- 精确匹配到 1 条 → 直接使用
- 模糊匹配到多条 → 列出让用户选择
- 未匹配到 → 停止，提示用户确认名称

### 2. 定位接手人

- 调用 `search-user` 搜索人名，获取 open_id
- 多个结果 → 列出让用户选择
- 未搜索到 → 停止，提示用户确认姓名

### 3. 收集移交信息

- 读取该需求的管理文件（摘要区）
- 读取 `dw-state.json` 中该需求的当前状态和 `daily_log` 记录
- 读取该需求目录下已产出的所有文档链接
- 通过 `git log` 获取该分支的改动文件列表

### 4. 生成移交文档

- **飞书后端**：在飞书 `AI-docs/需求文档/YYYYMMDD_[需求名]/` 目录下创建文档，标题：`[需求名]_移交摘要`
- **本地后端**：保存到 `{SKILLS_DIR}/daily-workflow/output/{项目名}/dw-docs/[需求名]_移交摘要.md`

内容结构：

```
## 需求概况
- 需求名称：xxx
- PRD 链接：xxx
- 一句话描述：xxx

## 当前进度
- 当前阶段：第X步（xxx）
- 已完成：xxx
- 待完成：xxx

## 代码信息
- Git 分支：feature/xxx
- 改动文件范围：（列出已改动的文件）

## 文档汇总
- 需求分析：[链接]
- 设计文档：[链接]（如已产出）
- AI走查报告：[链接]（如已产出）
- 单元测试报告：[链接]（如已产出）

## 待办事项
- [ ] xxx

## 关键决策记录
- [日期] xxx

## 已知风险 / 注意事项
- xxx

## 移交信息
- 移交人：@xxx
- 接手人：@xxx
- 移交时间：xxx
```

### 5. 通知接手人

- 在移交文档中使用 `mention-user` @ 接手人
- 在管理文件中添加评论，@ 接手人并说明已移交

### 6. 更新状态

- `dw-state.json` 中该需求 `status` 更新为"已移交-[接手人姓名]"
- `daily-log.md` 当天记录"移交给 xxx"
- 索引（飞书 `AI-docs/index` 或本地 `dw-index.md`）条目状态更新为"已移交"

### 7. 输出确认

"已移交 ✓，移交文档已创建并通知 @xxx"

## 接手方操作

接手方无需记住额外命令，操作流程：

1. `git checkout [分支名]` — 切到对应分支
2. `继续 dw` — AI 自动检测本地无该分支记录，从移交文档同步上下文后继续

具体的分支匹配和状态重建逻辑详见 `general-rules.md` 的"中断与恢复"章节。

如不使用本 skill：根据移交文档中的待办事项和文档链接手动继续。

## 跨机器移交

当接手方和移交方不在同一台机器时：

1. 移交方需要将以下文件通过 Git 或其他方式传递给接手方：
   - `dw-docs/[需求名]_移交摘要.md`
   - `dw-docs/[需求名]_*.md`（所有已产出的文档）
2. 接手方将文件放入自己项目的 `{SKILLS_DIR}/daily-workflow/output/{项目名}/dw-docs/` 目录
3. `git checkout [分支名]` 后执行"继续 dw"，AI 自动从移交文档重建本地状态
