# 需求移交规范

## 触发

用户说"移交 [需求名/分支名] 给 [人名]"

## 用途

将某个进行中的需求移交给其他同事。移交 = 把需求文件夹交给接手人，所有上下文自包含。

## 执行流程

### 1. 定位需求

- 用户提供需求名（支持模糊匹配）或分支名
- 从 `dw-state.json` 中匹配
- 精确匹配到 1 条 → 直接使用
- 模糊匹配到多条 → 列出让用户选择
- 未匹配到 → 停止，提示用户确认名称

### 2. 收集移交信息

- 读取该需求文件夹中已产出的所有文档
- 读取 `dw-state.json` 中该需求的当前状态和 `daily_log` 记录
- 通过 `git log` 获取该分支的改动文件列表

### 3. 生成移交文档

在 `dw-docs/{需求名}/handover.md` 中创建：

```markdown
## 需求概况
- 需求名称：xxx
- PRD 链接：xxx
- 一句话描述：xxx

## 当前进度
- 当前阶段：第X步（xxx）
- 已完成：xxx
- 待完成：xxx

## 代码信息
- Git 分支：feature/xxx
- 改动文件范围：（列出已改动的文件）

## 文档汇总
- 需求分析：[requirements.md](./requirements.md)
- 设计文档：[dev-design.md](./dev-design.md)（如已产出）
- AI走查报告：[cr-report.md](./cr-report.md)（如已产出）
- 单元测试报告：[unit-test-report.md](./unit-test-report.md)（如已产出）

## 待办事项
- [ ] xxx

## 关键决策记录
- [日期] xxx

## 已知风险 / 注意事项
- xxx

## 移交信息
- 移交人：xxx
- 接手人：xxx
- 移交时间：xxx
```

### 4. 更新状态

- `dw-state.json` 中该需求 `status` 更新为"已移交-[接手人姓名]"
- `dw-daily.md` 当天记录"移交给 xxx"
- `dw-index.md` 条目状态更新为"已移交"

### 5. 输出确认

"已移交 ✓，需求文件夹路径：`dw-docs/{需求名}/`，请将此文件夹交给接手人。"

## 接手方操作

1. 将收到的需求文件夹放入自己项目的 `dw-docs/` 目录
2. `git checkout [分支名]` — 切到对应分支
3. `继续 dw` — AI 自动从 `handover.md` 重建本地状态后继续

具体的分支匹配和状态重建逻辑详见 `general-rules.md` 的"中断与恢复"章节。

如不使用本 skill：根据移交文档中的待办事项和文档链接手动继续。
