# daily-workflow 学习机制

## 零、首次执行引导

> **AI 执行规则**：每次执行 skill 时检查下方日志表是否为空。如果为空（首次使用），在第一个确认点完成后主动告知用户：
>
> "💡 学习机制已启动：我会记录你的反馈（确认/修改/驳回）用于持续优化流程。你可以随时查看 `LEARNING.md` 了解我学到了什么。"
>
> 此提示只在日志表为空时触发一次。

**记录执行检查清单**（AI 自检）：
- [ ] 用户对当前步骤的输出做了修改？→ 记录到日志表
- [ ] 用户跳过了某个步骤？→ 记录到日志表
- [ ] 用户驳回了 AI 的建议？→ 记录到日志表
- [ ] 用户补充了 AI 未覆盖的内容？→ 记录到日志表
- [ ] 用户直接确认无修改？→ 不记录细节，但如果连续 3 次确认同一模式，标记为最佳实践

## 一、反馈触发点

| 场景 | 记录什么 | 反馈类型 |
|------|---------|---------|
| 用户跳过了某个步骤 | 哪一步、为什么跳过 | 驳回 |
| 用户调整了步骤顺序 | 哪几步、原来顺序、新顺序 | 修改 |
| 用户说"这个步骤没用" | 哪一步、原因 | 驳回 |
| 用户要求新增步骤 | 步骤名、插入位置、用途 | 补充 |
| 用户修改了状态流转 | 哪个状态、原流转、新流转 | 修改 |
| 用户调整了存储后端偏好 | 选了什么后端、为什么 | 修改 |
| 用户对某个辅助能力有反馈 | 哪个能力、什么反馈 | 修改 |
| 七步流程跑通一次无修改 | 什么场景 | 确认 |

## 二、反馈记录

### 日志表

| 日期 | 场景 | AI 输出 | 用户反馈 | 反馈类型 | 调整动作 | 是否已沉淀 |
|------|------|---------|----------|----------|----------|------------|
| 05/15 | 第一步需求分析 | 只在对话中输出分析报告，未写入飞书文档，未更新 daily-log | 用户指出遗漏 | 驳回 | 在 general-rules.md 新增"强制执行清单"章节，明确每步必做动作 | ✅ |

反馈类型：
- `确认` — 用户直接接受
- `修改` — 用户接受但调整了
- `驳回` — 用户完全否定
- `补充` — 用户添加了 AI 未覆盖的内容

### 记录规则

- 步骤跳过是强信号——说明该步骤可能不是所有场景都必需
- 状态流转调整影响全局，必须记录
- 辅助能力（周报、移交等）的反馈也需记录，用于优化各 references

## 三、策略优化

| 条件 | 动作 |
|------|------|
| 某步骤被 `驳回`（跳过）≥ 3 次 | 建议将该步骤改为可选步骤 |
| 新步骤被 `补充` ≥ 2 次 | 建议新增为正式步骤或可选步骤 |
| 状态流转被 `修改` ≥ 2 次 | 建议更新 SKILL.md 的状态定义 |
| 某辅助能力被 `修改` ≥ 2 次 | 建议更新对应的 references 文件 |
| 完整流程连续被 `确认` ≥ 3 次 | 固化为稳定版本，标记当前流程为验证通过 |

### 优化执行流程

1. **识别**：在流程执行过程中发现可优化点
2. **提出**：向用户描述问题和优化方案
3. **确认**：等待用户确认
4. **执行**：用户确认后，更新 SKILL.md 或 references 文件
5. **记录**：将变更记录到下方"已沉淀的规范更新"表中

## 五、用户偏好

偏好分两类，沉淀路径不同：

### 个人偏好（留在 LEARNING.md）

仅影响当前用户的 AI 交互体验，不适合推广给团队：

- [流程节奏] （暂无）— 如"别问这么多直接做"
- [存储偏好] （暂无）— 如"不用飞书，本地就行"
- [输出粒度] （暂无）— 如"设计文档不用写这么细"

### 团队规范（沉淀到 references/）

经验证有效且适用于团队所有成员的规则，应沉淀到对应的 references 文件：

- [编码规范] → `coding-standards/references/tech-stack.md`
- [CR 检查项] → `cr-general/references/specialized-checks.md`
- [测试策略] → `unit-testing/references/frontend-testing.md`
- [文档模板] → `development-design/references/design-template.md`

**沉淀判定规则**：
- 连续确认 ≥ 3 次 + 适用于所有团队成员 → 沉淀到 references（团队规范）
- 连续确认 ≥ 3 次 + 仅适用于个人习惯 → 留在 LEARNING.md（个人偏好）
- 不确定时，先记录在 LEARNING.md，积累更多数据后再判断
