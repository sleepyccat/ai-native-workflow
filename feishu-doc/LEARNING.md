# 飞书文档 Skill 学习机制

## 零、首次执行引导

> **AI 执行规则**：每次执行 skill 时检查下方日志表是否为空。如果为空（首次使用），在首次写入飞书文档后主动告知用户：
>
> "💡 学习机制已启动：我会记录你对文档格式和内容的反馈用于持续优化输出风格。你可以随时查看 `LEARNING.md` 了解我学到了什么。"
>
> 此提示只在日志表为空时触发一次。

**记录执行检查清单**（AI 自检）：
- [ ] 用户修改了文档格式/排版？→ 记录到日志表（修改）
- [ ] 用户否定了某种写法？→ 记录到日志表（驳回）
- [ ] 用户补充了格式偏好？→ 记录到日志表（补充）
- [ ] 用户直接接受了文档输出？→ 标记确认

## 一、反馈触发点

| 场景 | 记录什么 | 反馈类型 |
|------|---------|---------|
| 飞书文档格式渲染异常（换行丢失、表格错乱等） | 什么操作、用了什么格式、实际渲染效果 | 驳回 |
| 用户纠正了飞书编辑操作方式 | 哪个操作、AI 怎么做的、用户怎么做的 | 修改 |
| 发现新的飞书 MCP 限制或 workaround | 限制描述、解决方案 | 补充 |
| 飞书文档操作成功，格式正确 | 什么类型的文档、用了什么操作 | 确认 |
| config.json 校验逻辑需要调整 | 什么情况漏检了 | 补充 |
| 表格操作出现了误改其他内容的情况 | 什么操作、用了什么定位方式 | 驳回 |

反馈类型：
- `确认` — 用户直接接受
- `修改` — 用户接受但调整了
- `驳回` — 用户完全否定
- `补充` — 用户添加了 AI 未覆盖的内容

### 记录规则

- 格式渲染异常是高价值信号——说明写作规范有遗漏或不准确
- 编辑操作导致的误改也是强信号——说明编辑规范需要更严格的规则
- 新发现的 MCP 限制必须记录，用于更新编辑规范

## 三、策略优化

| 条件 | 动作 |
|------|------|
| 同一类格式问题被 `驳回` ≥ 2 次 | 更新写作规范，新增对应的格式规则 |
| 同一类编辑操作问题被 `驳回` ≥ 1 次 | 立即标记为高优，更新编辑规范 |
| 新的 MCP 限制被 `补充` ≥ 1 次 | 立即更新编辑规范，新增 workaround |
| 某类文档操作连续被 `确认` ≥ 3 次 | 固化为最佳实践 |

### 优化执行流程

1. **识别**：在飞书文档操作过程中发现可优化点
2. **提出**：向用户描述问题和优化方案
3. **确认**：等待用户确认
4. **执行**：用户确认后，更新 SKILL.md 对应规范
5. **记录**：将变更记录到下方"已沉淀的规范更新"表中
