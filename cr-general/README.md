# 🔍 代码走查 — 使用说明

> 一个代码走查 Skill，用 AI 对代码进行自动化走查，输出走查报告。

---

## 📌 两种使用模式

### 模式一：独立走查

不需要需求文档，直接指定文件范围：

```
代码走查 src/view/organization/businessSwitch/**/*.tsx
```

### 模式二：需求关联走查

配合 daily-workflow 使用，从设计文档自动获取文件范围：

```
CR（在 daily-workflow 第五步自动触发）
```

---

## 📢 常用命令

| 说什么 | 做什么 |
|--------|--------|
| `代码走查` + 文件路径 | 独立走查指定文件 |
| `CR` + 文件路径 | 同上 |
| `code review` | 走查（会询问文件范围） |

---

## 📋 走查维度

### ✅ 基础维度（每次必检）

1. ✅ 代码规范 — 命名、函数风格、类型定义、导入、注释、格式、路径别名
2. 🛡️ 逻辑健壮性 — 空值保护、JSON.parse 保护、条件判断完整性、表单重置、错误处理
3. 🌐 接口调用 — 请求时机、loading、防重提交、竞态条件、参数类型、保存后刷新
4. ⚡ 性能与可维护性 — 冗余 state、组件/函数大小、嵌套深度、防抖、硬编码、console.log
5. 💡 优化建议(P3) — 状态管理滥用、Hook 使用风险、状态提升、内联函数

### 🎯 可选维度

6. 🔗 与设计文档一致性 — 仅需求关联走查时检查
7. 🧩 专项检查 — 根据用户选择启用（专项检查清单详见 `references/specialized-checks.md`，可按团队替换）：
   - 🔄 UI 框架升级专项
   - ⚛️ 框架版本升级专项
   - 🎁 业务场景专项（如 IP 联名、营销活动等）
   - ✏️ 自定义专项（用户描述场景，AI 生成检查项）

---

## 🏷️ 严重程度

| 级别 | 含义 | 处理方式 |
|------|------|----------|
| 🔴 P0 | 紧急重要，必须现在就修改 | 立即修复 |
| 🟠 P1 | 重要但不紧急，可以稍后改 | 排期修复 |
| 🟡 P2 | 不是很关键，可以以后再改 | 视情况修复 |
| 🟢 P3 | 优化建议，提升代码质量 | 有空再改 |

---

## 📊 输出

走查报告默认在对话中展示，也可以写入飞书文档。包含：
- 📊 走查概览（各维度通过/问题数统计）
- 📝 问题详情表格（文件、类型、描述、严重程度、修复建议、是否已修复）
- 💡 AI 建议和风险提示

---

## 个性化配置

`references/` 目录存放用户可编辑的引导配置，换团队/换技术栈时替换即可：

- `specialized-checks.md` — 专项检查清单（UI 框架升级、框架版本升级、业务场景等）

## 🧠 自我学习

本 skill 具备独立的学习和反馈机制，详见 `LEARNING.md`。

- 每次用户对 AI 输出做修改/驳回/补充时自动记录反馈
- 同类修改 ≥2 次建议更新规范，驳回 ≥1 次下次规避，确认 ≥3 次固化最佳实践
- 所有学习记录和沉淀的规范更新都在 `LEARNING.md` 中可追溯

## 飞书集成（可选）

本 skill 支持三种输出方式：
1. **对话输出**（默认）：直接在对话中展示
2. **飞书文档**：需安装 `feishu-doc` skill 并配置凭证
3. **本地 MD 文件**：自动保存到 `{SKILLS_DIR}/cr-general/output/{项目名}/`
