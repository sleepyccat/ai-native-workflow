# 提测文档 Skill 学习机制

## 一、反馈触发点

| 场景 | 记录什么 | 反馈类型 |
|------|---------|---------|
| 用户修改了提测文档模板字段 | 哪个字段、AI 填的什么、用户改成什么 | 修改 |
| 用户删除了某个字段 | 哪个字段、原因 | 驳回 |
| 用户要求新增字段 | 字段名、用途、填写方式 | 补充 |
| 用户修改了固定值 | 哪个字段、旧值、新值 | 修改 |
| 用户直接接受了提测文档 | 什么场景 | 确认 |
| 自动填充的字段值有误 | 哪个字段、AI 填的、正确值 | 修改 |

## 二、反馈记录

### 日志表

| 日期 | 场景 | AI 输出 | 用户反馈 | 反馈类型 | 调整动作 | 是否已沉淀 |
|------|------|---------|----------|----------|----------|------------|

反馈类型：
- `确认` — 用户直接接受
- `修改` — 用户接受但调整了
- `驳回` — 用户完全否定
- `补充` — 用户添加了 AI 未覆盖的内容

### 记录规则

- 字段值修改是高价值信号——说明自动填充逻辑或固定值需要调整
- 新增字段意味着模板不完整，必须记录
- 固定值被修改时，考虑是否应改为可配置项

## 三、策略优化

| 条件 | 动作 |
|------|------|
| 同一字段被 `修改` ≥ 2 次 | 建议调整该字段的自动填充逻辑或默认值 |
| 字段被 `驳回`（删除）≥ 1 次 | 建议从模板移除该字段 |
| 新字段被 `补充` ≥ 2 次 | 建议新增到模板 |
| 某个模板连续被 `确认` ≥ 3 次 | 固化为稳定模板 |

### 优化执行流程

1. **识别**：在提测文档生成过程中发现可优化点
2. **提出**：向用户描述问题和优化方案，说明影响 references 中的哪个文件
3. **确认**：等待用户确认，不自行修改
4. **执行**：用户确认后，更新 references 对应文件
5. **记录**：将变更记录到下方"已沉淀的规范更新"表中
